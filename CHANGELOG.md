# Changelog

This project follows [Epoch Semantic Versioning](https://antfu.me/posts/epoch-semver): versions are `{EPOCH * 100 + MAJOR}.MINOR.PATCH`, starting at epoch 1 (`100.0.0`). A change to the first number can break your app; minor and patch releases don't. Moving to a new `@convex-dev/workflow` version changes the first number.

## Unreleased

The first release, for `@convex-dev/workflow` 0.4.10.

- Per-workflow migrations: `workflow.define({ migrations: [migration(id, (h) => ...)] })`. A migration rewrites a run's recorded history into the shape the current handler expects: insert a finished stand-in with its result, remove, rename (to a call with a custom `name` too), update a step's args or result, or update the workflow's own args. An insert where no journal entry follows does nothing, so a run that hadn't got past that point makes the call for real; `atEnd: true` inserts the stand-in anyway. Each run records the ids applied to it and applies the missing ones, in order, the next time it replays, so an installation can skip releases. Empty and duplicate ids throw when the workflow is defined.
- A run is paused instead of failed when its history doesn't match the code (including code that returns before the end of it), when its args don't match the validator and it has history, when the handler throws during replay where a migration may be the cause, when a migration throws, when its applied ids aren't the start of the code's list (a rollback), and when its overlay would pass 512 KiB. A throw that passes on the failure of one of the newest recorded steps, taken from the journal, fails the run, as before, even when migrations edited its history. A pause commits nothing of the handler run, and its detail is cut to 8,192 characters (a mismatch's to about twice that). A paused run is retried after about 1 minute, 10 minutes, 1 hour, then every 6 hours, ±20%; a retry whose workflow mutation throws keeps the pause and records the error as `lastError`. `onPause` in the manager's options is called when a run pauses, and again when the reason or step changes, with the attempts and the reason before.
- `WorkflowManager.paused` (paginated, by workflow, in the order runs paused), `resume`, `resumeAll` (one retry of each run paused when it's called, 100 ms apart), `restartFrom` and `fail` for paused runs. `resume` and `restartFrom` check the pause in the retry's own transaction. `restartFrom` throws for a position past the end of the history, or one read before a release added migrations or moved the paused step. `fail` claims the run first, so no retry resumes it meanwhile. `cancel` also ends a pause. `restart` takes a position, step name or step reference in the history, stores it on the run's record, throws for a position past the end, and restarts a canceled run that was waiting on an event. `cleanup` also deletes the records of the run and of the child workflows upstream deletes with it, and the record of a workflow that's already gone. A run whose workflow is gone loses its record at its next retry.
- The `workflowMigrations` component, with one row per run: its applied migrations, their edits, its pause and the row's format. A run with nothing applied and no overlay has no row.
- Test helpers in `@dev-marzahn/convex-workflow-migrations/test`: `expectReplays(workflow, histories)` (replays recorded histories against the current handler of the workflow mutation, with the same replay and rules a handler run uses, and no Convex backend), `history` (builds one by hand), `migrate(workflow, history)` (the history after the migrations), `expectEdits` (fails for a migration that changed nothing) and, for convex-test, `register`.
- `convex-workflow-migrations histories <workflow>`: exports a workflow's run histories from a deployment as JSON, for `expectReplays`, with each record's pending restart, a warning that they hold production data, and `--redact <module>` to scrub them, overlays included. It refuses to export when the workflow has more runs than `--max-runs`, unless `--allow-partial`, and stops at a record a newer version of the package wrote.
- Upstream's exports are re-exported, except `defineWorkflow` and the standalone `cancel`, `restart` and `cleanup`, which bypass the migrations or the run's record.
