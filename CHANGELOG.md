# Changelog

This project follows [Epoch Semantic Versioning](https://antfu.me/posts/epoch-semver): versions are `{EPOCH * 100 + MAJOR}.MINOR.PATCH`, starting at epoch 1 (`100.0.0`). A change to the first number can break your app; minor and patch releases don't.

## Unreleased

- The first release, as `@dev-marzahn/convex-workflow-migrations`, for `@convex-dev/workflow` 0.4.10: per-workflow migrations. `migration(id, fn)`, listed in `workflow.define({ migrations })`, rewrites a run's recorded history into the shape the current handler expects. Each run's record in the `workflowMigrations` component, written when the run is created, says which migrations it has had; the pending ones apply at its next replay, so a run from any older release replays on the newest code. A run that can't replay pauses instead of failing, with a reason and detail, and nothing of that handler run is saved; it's retried with backoff (1 minute, 10 minutes, 1 hour, then every 6 hours), so deploying the fix resumes it. The manager takes a required `onPause` (or `null`), and adds `paused`, `resume` and `fail`; `cancel` and `cleanup` end the pause too. `restart({ from })` refuses a run whose migrations edited its history. `/replay` has `history()`, `expectReplays`, which reports why a run would pause, and `migrate`, without Convex; `/test` adds `register(t)` for convex-test. This replaces the earlier, unreleased `step.patched()` design and its predeploy check.
- The `convex-workflow-migrations histories <workflow>` CLI exports a workflow's running runs, paused ones included, and its newest succeeded ones, from a deployment as JSON `RecordedHistory[]` for `expectReplays`, through the app's `convex run`; `--before-adoption` exports from a deployment without the migrations component. `--max-scan` bounds the runs it reads, and it exits with 1 when that stopped it, unless `--allow-partial`; `--max-steps` cuts long runs and marks them `truncated`; a run whose record kept changing while it was read is marked `unstable`; a run whose journal is over 8 MiB is left out, with a note. It exits with 2 on a usage, deployment or file-write error, or when there are no runs of that name. `RecordedHistory` has `truncated`, `unstable` and `encoding`: `expectReplays` and `migrate` fail a `truncated` or `unstable` history, and `/replay` decodes an `encoding: 'json'` export's int64s, bytes and special floats. `expectReplays` throws on an empty list.
